## 1. Общая информация

*   **Базовый URL:** `http://localhost:8080`
*   **Формат данных:** Все запросы и ответы, если не указано иное, имеют формат `application/json`.
*   **Аутентификация:** Большинство запросов требуют Access Token в заголовке `Token`. Подробнее в разделе [Система токенов](#5-система-токенов).
*   **Cookies:** Для работы механизма обновления токенов клиент должен принимать и отправлять HttpOnly cookies. Убедитесь, что в ваших HTTP-клиентах (например, `fetch`, `axios`) включена опция `credentials: 'include'`.

## 2. Аутентификация и регистрация

### Регистрация студента

Запрос на создание новой учетной записи студента. В случае успеха возвращается временный идентификатор сессии (`Session ID`) для подтверждения email.

```
POST /auth/students
```

#### Тело запроса (`application/json`)

| Параметр | Тип | Обязательный | Описание |
| :--- | :--- | :---: | :--- |
| `email` | `string` | да | Email пользователя (макс. 255 символов). |
| `password` | `string` | да | Пароль. **Требования:** 8-72 символа, минимум одна заглавная буква (A-Z), одна строчная (a-z) и одна цифра (0-9). |
| `device_id` | `string` | да | Уникальный идентификатор устройства (5-100 символов). |
| `birth_date` | `string` | да | Дата рождения в формате ISO 8601 (`YYYY-MM-DDTHH:MM:SSZ`). |

#### Пример запроса

```json
{
  "email": "ivan@example.com",
  "password": "StrongPass1",
  "device_id": "web_chrome_abc123",
  "birth_date": "2008-05-15T00:00:00Z"
}
```

#### Ответы

| Статус | Заголовки | Тело ответа | Описание |
| :--- | :--- | :--- | :--- |
| `200 OK` | `Token: <session_id>` | - | Успешная регистрация. Заголовок `Token` содержит Session ID со сроком жизни **7 минут**. |
| `400 Bad Request` | - | `Bad request` | Ошибка валидации входных данных (например, неверный формат email или пароля). |
| `409 Conflict` | - | `User with this email already exists` | Пользователь с таким email и ролью "intern" уже существует. |
| `422 Unprocessable Entity` | - | `User must be at least 16 years old` | Возраст пользователя менее 16 лет. |

---

### Регистрация компании

Запрос на создание учетной записи представителя компании. Проверяет существование и активность компании по ИНН через внешний сервис. В случае успеха возвращает `Session ID`.

```
POST /auth/company
```

#### Тело запроса (`application/json`)

| Параметр | Тип | Обязательный | Описание |
| :--- | :--- | :---: | :--- |
| `inn` | `string` | да | ИНН организации (10 или 12 цифр). |
| `email` | `string` | да | Email представителя компании (макс. 255 символов). |
| `password` | `string` | да | Пароль (требования как у студента). |
| `device_id` | `string` | да | Уникальный идентификатор устройства (5-100 символов). |

#### Пример запроса

```json
{
  "inn": "7707083893",
  "email": "hr@company.ru",
  "password": "SecurePass456!",
  "device_id": "iphone_app_xyz"
}
```

#### Ответы

| Статус | Заголовки | Тело ответа | Описание |
| :--- | :--- | :--- | :--- |
| `200 OK` | `Token: <session_id>` | - | Успешная регистрация. |
| `400 Bad Request` | - | `Bad request` | Ошибка валидации входных данных. |
| `404 Not Found` | - | `Company with this TIN not exists` | Компания с таким ИНН не найдена или ее статус не "ACTIVE". |
| `409 Conflict` | - | `User with this email already exists` | Пользователь с таким email и ролью "company" уже существует. |
| `502 Bad Gateway` | - | `External service temporarily unavailable...` | Ошибка при обращении к внешнему сервису проверки компании. |

### Подтверждение email

Подтверждение email с помощью кода, отправленного на почту. В случае успеха возвращает Access и Refresh токены.

```
POST /auth/students/verify   # Для студента
POST /auth/company/verify    # Для компании
```

#### Заголовки запроса

*   `Content-Type: application/json`
*   `Token: <session_id>` (получен при регистрации)

#### Тело запроса (`application/json`)

| Параметр | Тип | Обязательный | Описание |
| :--- | :--- | :---: | :--- |
| `code` | `string` | да | 6-значный числовой код подтверждения. |

#### Пример запроса

```json
{
  "code": "482915"
}
```

#### Ответы

| Статус | Заголовки | Тело ответа | Описание |
| :--- | :--- | :--- | :--- |
| `200 OK` | `Token: <access_token>`<br>`Set-Cookie: refresh_token=<value>; HttpOnly; ...` | - | Успешное подтверждение. Возвращается Access Token (JWT) и устанавливается Refresh Token в Cookie. |
| `400 Bad Request` | - | `Bad request` | Тело запроса не прошло валидацию (например, код не из 6 цифр). |
| `400 Bad Request` | - | `Invalid verification code format` | Код имеет неверный формат. |
| `400 Bad Request` | - | `Verification code expired` | Время жизни сессии (7 минут) истекло. |
| `429 Too Many Requests` | - | `Too many invalid attempts` | Превышен лимит попыток подтверждения. |

---

### Запрос нового кода

Повторная отправка кода подтверждения на email, если предыдущий не пришел или истек, но сессия (`SessionID`) еще активна.

```
POST /auth/newverify
```

#### Заголовки запроса

*   `Token: <session_id>` (актуальный идентификатор сессии)

*Тело запроса отсутствует.*

#### Ответы

| Статус | Тело ответа | Описание |
| :--- | :--- | :--- |
| `200 OK` | - | Новый код отправлен. Таймер жизни сессии обновлен. |
| `500 Internal Server Error` | `Internal server error` | Ошибка сервера (например, проблемы с Redis). |

*Примечание: Структура `UserAuth` также содержит поле `birth_date`, но для входа оно не используется и не обязательно.*

#### Пример запроса

```json
{
  "email": "ivan@example.com",
  "password": "StrongPass1",
  "device_id": "web_chrome_abc123"

```

#### Ответы

| Статус | Заголовки | Тело ответа | Описание |
| :--- | :--- | :--- | :--- |
| `200 OK` | `Token: <access_token>`<br>`Set-Cookie: refresh_token=<value>; HttpOnly; ...` | - | Успешный вход. |
| `400 Bad Request` | - | `Bad request` | Ошибка валидации. |
| `401 Unauthorized` | - | `Invalid password` | Указан неверный пароль. |

| `429 Too Many Requests` | - | `Too many invalid attempts` | Превышен лимит попыток входа. |

## 3. Профиль пользователя

Все эндпоинты этого раздела требуют **авторизации** (заголовок `Token: <access_token>`). Если срок действия Access Token истек, сервер попытается автоматически выпустить новый, если есть действующий Refresh Token в cookies.

### Профиль студента

#### Обновление профиля

```
PUT /my/profile/put
```
*Требует роль: `intern`*

##### Тело запроса (`application/json`)

Все поля являются **опциональными**. Отправьте только те, которые необходимо обновить.

| Параметр | Тип | Описание |
| :--- | :--- | :--- |
| `first_name` | `string` | Имя (макс. 100 символов). |
| `last_name` | `string` | Фамилия (макс. 100 символов). |
| `birth_date` | `string` | Дата рождения (ISO 8601). Возраст должен быть не менее 16 лет. |
| `location` | `string` | Местоположение (макс. 200 символов). |
| `university` | `string` | Университет (макс. 200 символов). |
| `degree` | `string` | Ученая степень (макс. 100 символов). |
| `bio` | `string` | Краткая биография (макс. 2000 символов). |
| `experience` | `string` | Опыт работы (макс. 5000 символов). |
| `image` | `string` | URL изображения профиля (обычно устанавливается через `/my/avatar/put`). |

##### Пример запроса

```json
{
  "first_name": "Иван",
  "last_name": "Петров",
  "bio": "Студент 4-го курса."
}
```

##### Ответы

| Статус | Тело ответа | Описание |
| :--- | :--- | :--- |
| `200 OK` | - | Профиль успешно обновлен. |
| `401 Unauthorized` | `User Unauthorized` | Проблема с аутентификацией. |
| `403 Forbidden` | `Access denied: insufficient permissions` | Попытка доступа пользователем с ролью, отличной от `intern`. |
| `422 Unprocessable Entity` | `User must be at least 16 years old` | Указана дата рождения, соответствующая возрасту < 16 лет. |

#### Получение профиля

```
GET /my/profile
```
*Требует роль: `intern`*

##### Ответы

| Статус | Тело ответа |
| :--- | :--- |
| `200 OK` | `{ "email": "...", "profile": { ... } }`|

##### Пример ответа (`200 OK`)

```json
{
  "email": "ivan@example.com",
  "profile": {
    "first_name": "Иван",
    "last_name": "Петров",
    "birth_date": "2008-05-15T00:00:00Z",
    "location": "Москва",
    "university": "МГУ",
    "degree": "Бакалавр",
    "bio": "Студент 4-го курса.",
    "experience": null,
    "image": null
  }
}
```

### Аватар

#### Установка или обновление аватара профиля

Загружает изображение на сервер и устанавливает его как аватар для текущего пользователя. Доступно как для студентов, так и для компаний.

```
PUT /my/avatar/put
```
*Требует авторизацию (любая роль).*

##### Запрос (`multipart/form-data`)

| Параметр | Тип | Обязательный | Описание |
| :--- | :--- | :---: | :--- |
| `avatar` | `File` | да | Файл изображения. Максимальный размер: **10 МБ**. Допустимые форматы: JPEG, PNG. |

##### Ответы

| Статус | Тело ответа | Описание |
| :--- | :--- | :--- |
| `200 OK` | `"http://<host>/t-match-storge/user:<id>:avatar"` | Успешная загрузка. Возвращает URL нового аватара. |
| `400 Bad Request` | `Bad request` | Ошибка в запросе (например, файл не прикреплен или слишком большой). |
| `401 Unauthorized` | `User Unauthorized` | Проблема с аутентификацией. |
| `500 Internal Server Error` | `Internal server error` | Ошибка сохранения файла или обновления записи в БД. При внутренней ошибке файл может быть удален из хранилища для обеспечения консистентности. |

## 4. Стажировки

Все эндпоинты этого раздела требуют **авторизации** (заголовок `Token: <access_token>`).

### Создание стажировки

```
POST /internships
```
*Требует роль: `company`*

#### Тело запроса (`application/json`)

| Параметр | Тип | Обязательный | Описание |
| :--- | :--- | :---: | :--- |
| `title` | `string` | да | Заголовок стажировки (макс. 200 символов). |
| `description` | `string` | да | Описание стажировки (макс. 5000 символов). |
| `salary` | `int` | нет | Зарплата (если не указана — `0`). |
| `location` | `string` | да | Место проведения (макс. 200 символов). |
| `duration_month` | `int` | да | Продолжительность в месяцах (минимум 1). |

#### Пример запроса

```json
{
  "title": "Стажер-разработчик Python",
  "description": "Мы ищем активного стажера...",
  "salary": 50000,
  "location": "Москва",
  "duration_month": 3
}
```

#### Ответы

| Статус | Тело ответа | Описание |
| :--- | :--- | :--- |
| `200 OK` | - | Стажировка создана. |
| `400 Bad Request` | `Bad request` | Ошибка валидации данных. |
| `401 Unauthorized` | `User Unauthorized` | Проблема с аутентификацией. |
| `403 Forbidden` | `Access denied: insufficient permissions` | Попытка создания не от лица компании. |
| `500 Internal Server Error` | `Internal server error` | Ошибка при сохранении в БД. |

---

### Получение стажировки по ID

```
GET /internships/:id
```

*Примечание: Этот эндпоинт **не требует авторизации**.*

#### Параметры пути

| Параметр | Тип | Описание |
| :--- | :--- | :--- |
| `id` | `int` | ID стажировки. |

#### Пример запроса

```
GET /internships/15
```

#### Ответы

| Статус | Тело ответа | Описание |
| :--- | :--- | :--- |
| `200 OK` | `{ "id": 15, "title": "...", ... }` | Полная информация о стажировке. |
| `410 Gone` | `Internship is archived` | Стажировка помещена в архив и недоступна для публичного просмотра. При этом компания-владелец все еще может ее видеть. |
| `500 Internal Server Error` | `Internal server error` | Ошибка при запросе к БД. |

#### Пример ответа (`200 OK`)

```json
{
  "id": 15,
  "company_id": 5,
  "title": "Стажер-разработчик Python",
  "description": "Мы ищем активного стажера...",
  "salary": 50000,
  "location": "Москва",
  "is_archived": false,
  "duration_month": 3,
  "created_at": "2024-03-15T10:30:00Z"
}
```

| `400 Bad Request` | `Bad request` | Ошибка валидации или неверный `id`. |

```
DELETE /internships/delete/15
```

#### Ответы

| `403 Forbidden` | `Access denied: insufficient permissions` | Доступ запрещен: пользователь не компания или пытается архивировать чужую стажировку. |

## 5. Система токенов

| Токен | Способ передачи | Время жизни | Назначение |
| :--- | :--- | :--- | :--- |
| **Session ID** | Заголовок `Token` | 7 минут | Идентификатор сессии для верификации email. |
| **Access Token** | Заголовок `Token` | 15 минут | JWT для авторизации при доступе к защищенным ресурсам API. |
| **Refresh Token** | `HttpOnly` Cookie `refresh_token` | 7 дней | JWT для бесшовного обновления Access Token без необходимости повторного входа в систему. |

**Механизм обновления Access Token:**
1.  Клиент отправляет запрос с истекшим Access Token.
2.  Сервер проверяет Refresh Token из Cookie.
3.  Если Refresh Token валиден, сервер генерирует новый Access Token и возвращает его в **заголовке `Token`** ответа на исходный запрос.
4.  Клиент должен извлечь новый Access Token из заголовка ответа и использовать его для будущих запросов.

## 6. Обработка ошибок

В теле ответа с ошибкой всегда возвращается строка с ее описанием.

| HTTP Код | Сообщение в теле ответа | Возможная причина |
| :--- | :--- | :--- |
| `400` | `Bad request` | Невалидный JSON, неверный формат полей в запросе. |
| `400` | `Invalid verification code format` | Код подтверждения не соответствует формату. |
| `400` | `Verification code expired` | Истек срок жизни `Session ID`. |
| `401` | `Invalid password` | Неверный пароль при попытке входа. |
| `401` | `User Unauthorized` | Access Token отсутствует, невалиден или истек, а обновление не удалось. |
| `403` | `Access denied: insufficient permissions` | Роль пользователя не имеет прав на данный эндпоинт (например, компания пытается обновить профиль студента или изменить чужую стажировку). |
| `404` | `User with this email not exists` | Попытка входа с несуществующей почтой. |
| `404` | `Company with this TIN not exists` | ИНН не найден в справочнике или компания неактивна. |
| `409` | `User with this email already exists` | Попытка повторной регистрации. |
| `410` | `Internship is archived` | Попытка получить стажировку, которая была помещена в архив. Владелец стажировки все еще может ее видеть. |
| `422` | `User must be at least 16 years old` | Недостаточный возраст пользователя. |
| `429` | `Too many invalid attempts` | Сработало ограничение частоты запросов. |
| `502` | `External service temporarily unavailable...` | Ошибка при обращении к стороннему API (DADATA). |
| `503` | `Cache service temporarily unavailable` или `Failed to send email...` | Сервис временно недоступен (Redis, почтовый сервер). |
| `500` | `Internal server error` | Внутренняя ошибка сервера (БД, генерация JWT и т.д.). |

## 7. Дополнительная информация

### CORS и Preflight-запросы

Сервер поддерживает CORS для указанных в конфигурации источников, методов и заголовков. Все эндпоинты автоматически отвечают `200 OK` на предварительные запросы `OPTIONS`. Убедитесь, что ваш клиент корректно отправляет запросы `OPTIONS`, если это необходимо браузеру.

### Rate Limiting (Ограничение частоты запросов)

Для защиты от злоупотреблений на всех эндпоинтах установлены лимиты на количество запросов в минуту.

| Эндпоинт | Лимит (запросов в минуту) |
| :--- | :--- |
| `POST /auth/students` | 20 |
| `POST /auth/students/verify` | 60 |
| `POST /auth/newverify` | 7 |
| `POST /auth/students/login` | 30 |
| `POST /auth/company` | 20 |
| `POST /auth/company/verify` | 60 |
| `POST /auth/company/login` | 30 |
| `PUT /my/profile/put` | 100 |
| `GET /my/profile` | 120 |
| `PUT /my/avatar/put` | 100 |
| `PUT /my/company/profile/put` | 100 |
| `GET /my/company/profile` | 120 |
| `POST /internships` | 12 |
| `PUT /internships/update/:id` | 12 |
| `DELETE /internships/delete/:id` | 5 |

*Примечание: Публичный эндпоинт `GET /internships/:id` не имеет ограничения по частоте запросов.*

Ключом для лимита является связка идентификатора (ID пользователя для авторизованных или Session ID для неавторизованных) и эндпоинта. При превышении лимита возвращается ошибка `429 Too Many Requests`.
